# 统一八维试用候选版

当前开发候选测量版本 `ge8-20261016.12`，尚未安装到真实入口；真实入口仍使用已验证的`.11`。A、B、C、E 已接入同名同序八维、64个观察点、冻结事实与模板、逐点原话核验及五采样评分；D和历史会话保留旧定义。历史版本工程验证保留如下，`.12`的当前验证状态见末节；尚未提升为稳定 main。

后续试用修复：导演两次取证失败时拒收本轮非法证据，保留作答并按冻结任务继续中性追问，由独立Judge核对完整对话；不放宽引用校验或补0。已保存但未完成的回答可继续处理，复用原消息与轮次；处理中断时暂停作答计时。`verify-ge8-director-recovery.cjs`以本机HTTP提供者复现四场景失败、SSE继续及原轮次恢复，外部模型请求为0。

真实验收包括12份固定对话各5次Judge，以及四场景完整链路。固定评分来自`.8`，其任务定义和Judge验收规则与`.9`相同，后续仅改进错误定位信息；没有把旧结果改写成新版实测。`.9`导演只增量提取最新作答，输出上限6000 token；旧快照保留原参数。E第一次评分不足5份合法样本，原失败记录保留；使用程序允许的最后一次评分重试后得到5份合法样本。B的五样本有逐维分歧和总分波动告警，报告保留待复核、完整总分为空；三轮角色技术失败使用冻结中性问题并留痕。没有静默模拟评分或放宽引用规则。

这些是量规合成作答的程序与内部一致性检查，不能当作独立专家评审、新版心理测量信效度、招聘阈值或真实人员成绩。

## 已实现的路径

- `backend/src/assessment/definitions.ts` 与 `observations.json` 是新版内容入口。每维2点，单维0—20，缺失为 null。`.3` 加入32维的具体高、中、低和缺失锚点，以及相邻领域边界。`.2` 定义单独归档，已有会话仍可续测；`.1` 仅保留于本地合成测试记录。合成样例不是经过实证校准的分数标准。
- `.4` 安装新版模板时统一为LF换行，使Windows与其他检出的模板哈希一致；`.2`、`.3` 原定义与已有模板另存，不改历史快照。
- `.5` 修复真实探测发现的缺失记录契约冲突：无证据不进入取证记录；导演获得本点观察定义，但不获得评分锚点；唯一一次修复请求带具体校验错误。`.4` 探测在2次请求后停止，未进入固定五采样批次；历史记录保留。
- `.6` 修复`.5`真实C探测中连续出现的JSON提前闭合：导演将证据数组放在最后；错误提示明确定位对象提前结束，仍严格拒绝非法内容。审计同时记录返回文本及解析/契约错误，不能把HTTP成功计为有效首答。`.5`的A、B探测通过，C失败后停止，共6次请求。
- `install.ts` 提供预演和事务安装，遇自定义旧情境冲突停止，不覆盖旧模板。旧场景正文存入私有安装记录，以便历史会话继续展示原任务卡。`seed` 仅允许空库初始化。
- `runtime.ts` 冻结实际模板正文、内容哈希、定义、模型参数、守护轮次及代码状态，并校验完整快照哈希。历史任务卡从会话快照显示。`.2` 的旧快照缺少守护配置时仅使用归档场景配置；不承诺补出当时未记录的信息。`audit.ts` 保存真实请求、返回、哈希和接口提供的 usage，同时保存实际执行进程的代码SHA、工作区状态及关键模块哈希。报告分别保留开始快照与评分执行版本，便于核对升级后续测和重试。密钥不进入快照或请求正文。后台必须配置本机 `ADMIN_SECRET`。
- `session.ts` 使用 LangGraph，保留质量门控、导演、守护、角色和结束后独立 Judge；事件实际写入消息后才计送达。候选人接口仅返回公开状态。普通 GET 和重复结束不会重新开启五路收费评分。
- `judge.ts` 对每路最多2次请求，严格检查重复 JSON 键、8维顺序、16点、分值和候选人原话；不足5份合法样本为技术失败。五份均 rated 才逐维去极值并取整。缺失、分歧、模拟报告不写正式总分。
- 前端保留 null、按报告内冻结顺序展示、提供证据消息跳转；缺维不画闭合雷达。统计按情境、测量版本及实际模型配置分组。

## 本地构建与安装

需要 Node 24、锁定的 npm 依赖和可用 Git。Windows 路径作为独立参数传入，支持中文和空格。

```powershell
npm ci
npm exec -w backend -- prisma generate
npm run backend:build
npm run frontend:build
npm test
npm run test -w frontend
```

新库使用 `node scripts/init-ge8.cjs <新库绝对路径>`；工具拒绝已存在的数据库，保留失败现场以便检查。已有库先一致性备份，再在复制库设置 `DATABASE_URL`，执行 `prisma migrate deploy`。已有库不重新执行 seed，然后运行：

```powershell
node backend/dist/src/assessment/install.js
node backend/dist/src/assessment/install.js --apply
node scripts/local-server.cjs --database <复制库绝对路径> --mode mock --port 17861
```

第一次是预演，第二次才安装。对同一安装ID重复执行不改内容。真实模式必须显式选 real，并在本机配置 API key；不得用离线模拟入口代替真实测试。

## 验证及恢复

`backend/scripts/verify-ge8.cjs` 仅接受名称为 `verification-*.db` 的独立库，检查四场景模拟对话、SSE、事件、空值报告、模板修订、重复结束与D旧版运行。合成标记 `【A1】` 等只给 mock 回归使用，不是正式作答要求，也不用于关键词打分。

`backend/scripts/verify-ge8-upgrade.cjs` 对一次性 `.2` 复制库检查自定义冲突、已知版本升级、四场景旧会话、并发结束、进程中断恢复和实际守护修正。管理员可 POST `/api/admin/sessions/:id/recover-turn` 或 `/retry-scoring`；活进程或未知锁拒绝操作。恢复轮次不调用模型，评分最多额外启动一批五采样；GET不会恢复收费任务。

`scripts/checkpoint.cjs` 使用 SQLite Backup API，保存 Git bundle、未提交差异、未跟踪文件、配置、实际模板、构建及恢复器。备份目录必须在源码仓库外，不能上传公开仓库。

`scripts/restore-local.cjs` 支持 `--dry-run`；实际恢复先保存当前现场，随后检出到新目录，验证数据库、匹配迁移、锁定依赖和独立启动，再以 `--switch` 更新本地 `stable-launch.json`。不删除旧目录、不强推、不降低数据库结构。升级后新增会话保留在恢复前检查点，不承诺旧代码读取新数据。

## v12：表现缺口可以评分，先补齐实际提问

`.12`冻结`response-quality/1`，引用仍使用同一平面协议2。充分性表示能否判断，不表示满足全部观察要求：已有行动但缺少理解检查、负责人或检查节点，按共同量规选择6—10或11—15，不能仅因少一个细节就留空。具体的主动表达在事实送达后也可评分，不要求一定被直接问到。

对明确中性问题后的有限回应，程序从实际消息核对逐点问题、事实时序和其后的候选人回应；有这类关联的partial可以支持0—15的相应分档，报告同时链接问题和原话。首次空泛回应不直接判0—5；partial进入0—5必须有实际追问后的负向证据。候选人没有回应、必要信息未提供和技术失败仍保留null，不按轮数或关键词缺失自动给低分。两个点已有可判断依据时，不能仅因表现有缺口拒绝评分。高档仍需两点充分。
